AQNWB::NWB::EventsTable Class Reference

A column-based table to store information about events, one event per row. Use EventsTable when each row is anchored at a single timestamp and duration is absent, optional, or mixed across rows. Additional columns may be added to store metadata about each event, such as the duration of the event. Examples include TTL pulses, licks, rewards, stimulus onsets, and detected ripples. Each EventsTable should hold events of a single type, so that all rows share the same set of per-event metadata columns. Detailed Description

A column-based table to store information about events, one event per row. Use EventsTable when each row is anchored at a single timestamp and duration is absent, optional, or mixed across rows. Additional columns may be added to store metadata about each event, such as the duration of the event. Examples include TTL pulses, licks, rewards, stimulus onsets, and detected ripples. Each EventsTable should hold events of a single type, so that all rows share the same set of per-event metadata columns. Events of different types (e.g., licks and stimulus presentations) should be stored in separate EventsTable instances.

Initialize the object.

Note
Handling of Optional Paths: If the EventsTable is being created in the /events group (e.g., /events/my_table), this method will automatically create the /events group if it does not already exist using the NWBFile::requireEventsGroup() helper method. This is because the /events group is optional in the NWB file structure and as such needs to be created on-demand. If the EventsTable is being created in a different path, this method will not create any parent groups, and it is the caller's responsibility to ensure that the parent group exists.

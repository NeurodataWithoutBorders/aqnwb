# Add a neurodata_type to AqNWB

The developer docs are the source of truth. Read them first and follow them over this file:
- `docs/pages/devdocs/registered_types.dox`: RegisteredType, the field macros, the Spec convention
  (section *How to define the Spec and initialize method of a RegisteredType*), and the
  `generate-types` command (including the AQNWB-TODO categories)
- `docs/pages/devdocs/integrating_extensions.dox`: types from NWB extensions
- `docs/pages/devdocs/testing.dox`: testing

## 1. Generate the starting point

```bash
mkdir -p gen/spec
uv run resources/utils/aqnwb_utils.py generate-spec <schema_dir> gen/spec   # only for new namespaces
uv run resources/utils/aqnwb_utils.py generate-types --generate-test-app <namespace.yaml> gen
```

- Types already implemented in `src/nwb` are not generated; the generated classes use them.
- Only take the files for the types you are adding. Do not commit the `gen` folder.

## 2. Move the files into the source tree

- Put the class in `src/nwb/<module>/<Type>.{hpp,cpp}`, where `<module>` follows the schema file
  (e.g., `nwb.ophys.yaml` -> `src/nwb/ophys/`). Types of extensions live in the user's project, not in AqNWB.
- Change the namespace from the generated one (e.g., `CORE`) to `AQNWB::NWB`, and use `#include "nwb/..."`
  paths. Match the style of the neighboring files: Doxygen comments, `std::cerr` error messages,
  `Status` handling.
- Add the `.cpp` file to `add_library(aqnwb_aqnwb ...)` in `CMakeLists.txt`. If the module has a CMake
  option (e.g., `AQNWB_ENABLE_OPHYS`), add the file under that option.
- Keep the `REGISTER_SUBCLASS` / `REGISTER_SUBCLASS_IMPL` names equal to the schema type and namespace.

## 3. Resolve all AQNWB-TODO markers

List them via `grep -rn "AQNWB-TODO" src/nwb/<module>`. Resolve one category at a time, using its reference implementation:

| Category | What to do | Reference |
|---|---|---|
| `child` | Owned neurodata_type objects are not in the Spec. Create them after `initialize` via `DEFINE_UNNAMED_REGISTERED_FIELD` create methods, or add nested specs for required children. | `src/nwb/NWBFile.hpp` |
| `table-columns` | Add the required columns to `createDefaultDataSpecs`, and check them with `checkRequiredColumnSpec` in `validateDataSpecs`. | `src/nwb/event/EventsTable.cpp` |
| `dataspec` | Dataset types (e.g., VectorData subtypes) need a nested `DataSpec` and a `createDataSpec` factory. | `src/nwb/event/TimestampVectorData.hpp` |
| `dtype` | Reference, compound, undefined, or `numeric` dtypes, and multi-dimensional datasets with a value. Restrict the allowed `BaseDataType`s in `validate()`. | `src/nwb/hdmf/table/DynamicTable.hpp` |
| `override` | Set the fixed or default value of an inherited field in the Spec constructor, and check it in `validate()`. | `src/nwb/ecephys/ElectricalSeries.hpp` |
| `parent-spec` | The parent class has no `Spec`. Add one to the parent first. | `src/nwb/RegisteredTypeSpec.hpp` |
| `link` | Unnamed links need custom handling. | `src/nwb/file/ElectrodeGroup.cpp` |
| `nwbfile-helper` | For acquisition types, add a function to create and initialize the objects. Prefer free functions in the module over new `NWBFile` members (see issue #213). | `src/nwb/NWBFile.cpp` (`createElectricalSeries`) |
| `write-helper` | Add a function to write data blocks by recording index. | `src/io/nwbio_utils.hpp` |
| `chunking` | Choose default chunking for acquisition datasets (e.g., one frame per chunk for images). | `src/nwb/NWBFile.cpp` (`createSpikeEventSeries`) |

Rules for the Spec and `initialize` (see the developer docs for details):
- Required fields use plain types and are checked in `Spec::validate()`. Optional fields use `std::optional`.
- `validate()` calls the base spec's `validate()` first. `initialize(const Spec&)` calls `Parent::initialize(spec)` first.
- Re-expose inherited setters with `INHERIT_SPEC_SETTER`, and document fields with a `///` comment above `DEFINE_SPEC_FIELD`.
- Never write to the file before validation succeeds.

## 4. Test

- Add `tests/test<Module>.cpp` (Catch2), or extend an existing test file, and register it in `tests/CMakeLists.txt`. Cover:
  - `initialize` from a Spec and reading back with the `read*` methods
  - `validate()` rejecting invalid specs, with no object created
  - writing data for acquisition types
- Write at least one `.nwb` file to `tests/data`, so that the CI `validate` job checks it with nwbinspector.
- Build and test with `cmake --preset=ci-<os>` (`ubuntu`, `macos`, or `windows`), then `cmake --build build` and `ctest --test-dir build --output-on-failure`. See `.github/copilot-instructions.md` for details.
- Run nwbinspector on the new `.nwb` files locally if possible:
  `nwbinspector <files> --threshold BEST_PRACTICE_VIOLATION`.

## 5. Finish

- Format: `cmake -D FORMAT_COMMAND=clang-format -P cmake/lint.cmake` (add `-D FIX=YES` to fix).
- Spelling: `codespell` on the changed files.
- Update `CHANGELOG.md` (section `[Unreleased]`) and the user docs, if the type is used during acquisition.
- Check that `grep -rn "AQNWB-TODO" src/` returns nothing.
- Pull requests are created as drafts and need review by a maintainer.
